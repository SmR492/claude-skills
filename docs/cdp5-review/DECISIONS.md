**Drift found in the repo today**

**What the sources say**

- Anthropic evals: "deterministic graders where possible, LLM graders where necessary"; grade each dimension separately with "clear, structured rubrics"; "vague rubrics produce inconsistent judgments"; give the judge an "Unknown" exit; grade outcomes, not paths; scoring may be weighted, binary or hybrid; calibrate the LLM judge against human experts; "Read the transcripts!".
- Anthropic success criteria: specific, measurable, achievable, relevant; multidimensional; define scale endpoints.
- Anthropic research system judge: "a single LLM call with a single prompt outputting scores from 0.0–1.0 and a pass-fail grade" — score and gate together.
- LLM-as-judge practice: 1–10 scales "rarely work well"; use binary or the lowest-precision scale that captures the distinction; rubric quality matters more than the scale; anchor examples per level; calibrate on 20–100 human-labelled cases before trusting the judge.
- Definition of Ready / INVEST: a binary gate before work starts; testable acceptance criteria; readiness test "QA can write test cases from the spec without asking" (the AI-era form of the Sachbearbeiter-Test); keep stories negotiable, do not over-specify.
- PRD review: verdict ship / revise / rethink; "an engineer can estimate without a follow-up meeting".
- Spec-driven development 2026: testable AC, non-goals, constraints, edge cases, agent-sized decomposition, reviewer sign-off; specs as validation gates; "for a small bug fix, the spec overhead isn't worth it" (rigor levels).

**Design of the one rubric (proposal)**

1. **Two layers, one file.** Layer 1 = gate: the §7 items, binary, labelled [det]/[jdg]; all must pass. Layer 2 = degree: the 7 weighted dimensions for prioritising gaps and tracking progress across iterations. Verdict = hybrid as in Anthropic's judge: pass/fail from layer 1 plus the weighted score, reported together. A high score never overrides an open gate item.
2. **Scales per the evidence.** Deterministic dimensions = fraction of checks met (what `konzept-lint` already computes). Judgment dimensions = three anchored levels (0 fails / 5 partial / 10 meets, each with a written anchor and an example) plus an explicit "Unknown: insufficient information" exit; no free 0–10.
3. **One threshold, in the policy only.** Doctrine paragraphs never carry a number; the shipped default policy sets it. Recommendation: 9.0 (the dogfood path 8.4 → ≥ 9.0 shows it is achievable in ≤ 2 iterations; the 8 from Bartels was a UC-clarity example).
4. **Single source.** Markdown policy is authored; `reife-rubrik.policy.json` is generated from it (D-2); `konzept-lint` reads the generated JSON and its `DEFAULT_WEIGHTS` are replaced by the policy's deterministic subset; konzept-reviewer loses the inline table and reads the policy passed in the brief; CI fails on drift between Markdown, JSON, lint defaults and agent text.
5. **Known-Issue record.** Every accepted risk and every dismissed lint flag is a line with decider, date, reason, source; the review output lists them.
6. **Calibration set.** Start with ~5 scored concepts (konzept.md v1.0 = 8.4 and v1.1 ≥ 9.0 are two), target 20; reproducibility test two runs ±0.2 (already in the agent) becomes a CI eval over the set.
7. **Rigor levels.** Full rubric for concepts (§29 modes A/B); a reduced gate (AC table, error cases, non-goals) for small changes; bug fixes exempt. Ties to A9 and §29.
8. **§10.7** Nachweis-Typ "Policy-Score" points to the policy file.

### A5 design: how the shared worker contract reaches every role (2026-10-19)

Verified mechanics (Claude Code docs, read 2026-10-19; the review's doc snapshot of 2026-10-12 agrees):

- Subagent frontmatter `skills` injects the full skill text at start, but "if a listed skill is missing or disabled … Claude Code skips it and logs a warning to the debug log" (sub-agents.md:615), and agent teams do not apply it: "Claude Code doesn't apply the definition's `skills` to a teammate in either display mode." Preloading always costs the full text per start.
- `SubagentStart` hook: fires "when Claude spawns a subagent with the Agent tool, when Claude resumes a subagent, and each time an in-process agent team teammate handles a new message"; matcher on the plugin-scoped type (`^cdp5-agents:`); returns `hookSpecificOutput.additionalContext`, placed "at the start of the conversation, before the first prompt"; re-injected only when the earlier copy left the context (prompt-cache friendly). Cannot block.
- `SubagentStop` hook: receives `last_assistant_message`, `agent_transcript_path`, `stop_hook_active`; `decision: "block"` with `reason` "keeps the subagent running and delivers `reason` to the subagent as its next instruction".
- Plugin hooks (`hooks/hooks.json`, `${CLAUDE_PLUGIN_ROOT}`) apply inside subagents; frontmatter `hooks`/`mcpServers`/`permissionMode` of plugin subagents are ignored (X10), so plugin-level hooks are the only enforcement point anyway.
- Skills: description always in context, body on invoke; supporting files load on demand; "every line is a recurring token cost".
- Third-party consensus (cybedefend, hidekazu-konishi, chudi.dev, ofox.ai): a hook is the only mechanism with a guaranteed trigger; CLAUDE.md, skills and agent prompts are model-interpreted; give each rule one owner, prose explains, hook enforces; do not duplicate a rule across CLAUDE.md, skill and hook.

Design (repo only, no Orbit):

| Layer | Mechanism | Purpose |
|---|---|---|
| Source | `plugins/cdp5-agents/skills/worker-contract/SKILL.md` (full contract, English) and a generated `core.md` (normative rules only, 6–10 lines) with header `WORKER-CONTRACT v<N> sha256:<12>` | one A1-master; core is derived, never hand-edited |
| Delivery | `hooks/hooks.json` → `SubagentStart`, matcher `^cdp5-agents:`, `node ${CLAUDE_PLUGIN_ROOT}/hooks/inject-contract.mjs` returns `core.md` plus the absolute path of `SKILL.md` as `additionalContext` (worded as facts). If `core.md` is missing or its hash does not match, it returns `CONTRACT-MISSING: do not start work, report this` and exits 2 | deterministic, covers subagents and in-process teammates, no model interpretation |
| Acknowledgement | every role's §5 (generated) carries the duty: first line of the final answer is `contract: v<N> <hash>` copied from the header. `SubagentStop` hook (same matcher) checks `last_assistant_message`; missing or wrong line → `decision: block`, reason: read `SKILL.md` and restate; blocks at most once (`stop_hook_active`) | a result without acknowledgement never reaches the orchestrator unchecked; also the orchestrator's cheap check |
| Lazy full text | §5 says: the full contract is at the path given in the header; Read it when a rule's application is unclear (severity scale, Stop-Retro format). `Read` fails loudly if the file is missing. No `skills:` preload, so no second copy and no silent-skip surface | tokens only when needed |
| CI | `node --test` without dependencies: hook returns core with the current hash; mutation: `core.md` removed → `CONTRACT-MISSING` + exit 2; generator drift: `core.md` equals the derivation from `SKILL.md`, every agent's §5 hash equals the current one; stop hook: message without ack → block, with ack → pass, `stop_hook_active` → no second block | satisfies D-4 (one firing test per known failure) |
| Teammates | `SubagentStart` covers in-process teammates per docs; the lead's brief carries the reference as well. Split-pane teammates: not verified | belt and braces |

Token estimate per agent start: core ≈ 120–180 tokens (cached), acknowledgement line ≈ 10; full text (≈ 600–900) only on demand. Preloading or inlining the full text would cost the full amount on every start.

Comparison with the repo today: `cdp5-agents` has 5 agent files with the method inline, no hooks, no skills and no §5; the "Pflicht-Vorlauf" (read doctrine via `cdp5-reference` or the bundled file, path in the brief) is prose only, exactly the class of rule the sources say belongs in a hook. The marketplace already ships one tested hook (`orbit-workflow` SessionStart, 9/9 tests, mutation-checked); the same harness carries the two new hooks. CLAUDE.md was rejected as carrier: it costs every request of every session and `omitClaudeMd` subagents would lose it.
