# Test-driven development (TDD)

Test-driven development (TDD) is a software development practice that emphasizes writing automated tests before writing code: developers write a failing test case describing an aspect of the code, then write the code to make it pass. TDD is part of the Agile methodology. Benefits include improved code quality, better test coverage, increased confidence in changes, and reduced debugging time, while drawbacks include being time-consuming, requiring more code, and being poorly suited to highly exploratory or experimental projects.

- Red: write a test that fails because the implementing code is not yet written
- Green: write the minimum code necessary to make the test pass
- Refactor: improve the code to be more maintainable, readable, and efficient
- Promotes a culture of continuous testing and improvement
